# GeoGuard server

Accounts and the username directory. The phone app talks to this over HTTPS;
only this service ever sees the database.

```
Flutter app ──HTTPS, session JWT──▶ this server ──▶ MongoDB Atlas
```

## Run locally

```bash
cd server
npm install
cp .env.example .env     # fill in the three values
node --env-file=.env src/index.js
curl localhost:8080/health
```

## Test

```bash
MONGODB_URI="..." JWT_SECRET=test-secret npm test
```

The validation tests run anywhere. The directory tests need `MONGODB_URI` and
skip themselves without it. They create and delete their own `test-sub-*`
users, so they are safe against a real cluster.

## The two credentials, and why they are different

This trips everyone up, so it is worth being exact.

| | Looks like | What it is for | Goes where |
|---|---|---|---|
| **API key** | `AIzaSy...` | Maps, Places, Firebase config | **Not used by this project** |
| **OAuth client ID** | `1234-abc.apps.googleusercontent.com` | Signing a user in | app + server |
| **OAuth client secret** | `GOCSPX-...` | Server-side web flows | **Never needed here** |

Google Sign-In needs the **OAuth client ID**. An `AIzaSy...` key cannot sign
anybody in — it is not an identity credential at all, and `google_sign_in`
will reject it.

## Getting the OAuth client IDs

1. <https://console.cloud.google.com> → pick or create a project.
2. **APIs & Services → OAuth consent screen**
   - User type: External
   - Fill in app name, support email, developer email
   - While in "Testing", add your own Google account under **Test users**, or
     sign-in fails with `access_denied`.
3. **APIs & Services → Credentials → Create credentials → OAuth client ID**

   **a) Android client** — the app is matched by package + certificate.
   - Package name: from `android/app/build.gradle` (`applicationId`). It is
     `com.example.veripic` today; change it before you ever publish, because
     `com.example.*` is rejected by the Play Store.
   - SHA-1 of your **release** keystore:
     ```bash
     keytool -list -v -keystore veripic-release.jks -alias YOUR_ALIAS
     ```
   - Also add the **debug** SHA-1, or sign-in fails on every dev build:
     ```bash
     keytool -list -v -keystore ~/.android/debug.keystore \
       -alias androiddebugkey -storepass android -keypass android
     ```
   - This client id is never typed anywhere. Google matches it automatically.

   **b) Web client** — counter-intuitive but required.
   - Create a second client, type **Web application**.
   - *This* id is the one you use, in two places:
     - server: `GOOGLE_WEB_CLIENT_ID`
     - app: `--dart-define=GOOGLE_SERVER_CLIENT_ID=...`
   - It is what makes Google mint an ID token whose `aud` the server can
     verify. Without it you get a token the server will refuse.

   Both must sit in the **same Google Cloud project**.

## Deploy to Render (free)

The repo root has a `render.yaml` blueprint, so Render sets the service up
from it.

1. Push this repo to GitHub.
2. <https://render.com> → **New → Blueprint** → pick the repo. Render reads
   `render.yaml`: root directory `server`, build `npm ci`, start `npm start`,
   health check `/health`, Node 22.
3. It asks for the values marked `sync: false`:
   - `MONGODB_URI` — Atlas connection string (a readWrite user on one database)
   - `GOOGLE_WEB_CLIENT_ID` — the **Web** OAuth client id
   - `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET`
   - `ADMIN_PASSWORD` — password for the admin account (see below)

   `JWT_SECRET` is generated by Render; `MONGODB_DB` and `ADMIN_USERNAME`
   come preset.
4. Atlas → Network Access → allow Render's outbound IPs (listed on the
   service's **Connect** tab), **not** `0.0.0.0/0`.
5. Copy the service URL — that is `GEOGUARD_API`.
6. Razorpay Dashboard → Settings → Webhooks → add
   `https://<service>.onrender.com/payments/webhook`, event
   `payment.captured`, and the same secret as `RAZORPAY_WEBHOOK_SECRET`.

The free instance sleeps after inactivity, so the first request after a quiet
spell takes ~30s. The app waits up to 60s and keeps a signed-in user signed in
meanwhile, so a sleeping server is slow rather than broken.

## Accounts, usernames and the admin

- **Everyone signs in with Google.** The app opens on the login page, then
  asks a new account to pick a username before letting them in.
- **Usernames are unique and permanent.** Lowercased, `[a-z0-9_]{3,20}`, with a
  unique index deciding who gets a name. They cannot be changed once set,
  because photos are addressed to a username and renaming would strand
  whatever is waiting in that inbox.
- **One admin account** signs in with a password instead, and has every paid
  feature without paying. Its name is `ADMIN_USERNAME` (default `doom`) and
  its password is `ADMIN_PASSWORD` — set only in the Render dashboard, never in
  the repo or the app. The name is reserved at startup so no Google user can
  claim it. Leave `ADMIN_PASSWORD` empty and the account is switched off.
  Password sign-in is limited to 10 attempts per IP per 15 minutes.

## Pro

One plan: **Rs 1 for 30 days**. Pro unlocks checking photos and downloading
the PDF report. Taking photos, sharing as a file and sending photos to another
user stay free.

- The price and period live in `PLANS` in `src/payments.js`. The app never
  sends a price, only the plan name.
- A payment is granted only after the server reproduces Razorpay's HMAC with
  the key secret. The order flips to `paid` atomically, so the app's confirm
  call and the webhook can both arrive and the month is still added once.
- Paying while Pro is still running adds 30 days on top of the time left.
- Who has Pro: `users.proUntil` in Mongo (a date, null if never paid), or
  `role: "admin"`. `pro` in every account response is worked out from these.

## Point the app at it

```bash
flutter run   --dart-define=GEOGUARD_API=https://your-service.onrender.com   --dart-define=GOOGLE_SERVER_CLIENT_ID=1234-abc.apps.googleusercontent.com
```

Without these the app runs exactly as before, with no login page — capture,
check, save senders by hand and share-as-file all work offline, and nothing is
behind a paywall.

## API

All routes except `/health`, `/auth/*`, `/payments/config` and
`/payments/webhook` need `Authorization: Bearer <session>`.

| Route | Body | Returns |
|---|---|---|
| `GET /health` | — | `{ok}` |
| `POST /auth/google` | `{idToken}` | `{token, user, needsUsername}` |
| `POST /auth/password` | `{username, password}` | `{token, user}` · admin only, 401 otherwise |
| `GET /me` | — | `{user, needsUsername}` |
| `POST /me/username` | `{username}` | `{user}` · 409 if taken or already set |
| `PUT /me/keys` | `{sharingCode, encryptionKey}` | `{user}` |
| `GET /users/available?u=` | — | `{available, reason}` |
| `GET /users/search?q=` | — | `{results[]}` (never includes you) |
| `GET /users/:username` | — | `{user}` |
| `POST /shares` | `{toUsername, ciphertextB64, wrappedKey, ephemeralPublicKey, sha256}` | `{share}` |
| `GET /shares/inbox` | — | `{shares[]}` |
| `GET /shares/:id/blob` | — | encrypted bytes |
| `DELETE /shares/:id` | — | `{ok}` |
| `GET /payments/entitlements` | — | `{pro, proUntil, user}` |
| `POST /payments/order` | `{plan: "pro"}` | Razorpay order |
| `POST /payments/verify` | `{orderId, paymentId, signature}` | `{pro, proUntil, user}` |

`user` for yourself includes `pro`, `proUntil` and `admin`.

Two rules the code enforces and the app depends on:

- **The fingerprint is always derived server-side** from the key it names. A
  client-supplied fingerprint is just a label an attacker chose, and it is the
  one value users compare out loud.
- **Search never returns an email.** Only username, display name, sharing code
  and fingerprint leave the server.
